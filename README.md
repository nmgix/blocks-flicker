# Моргающие компоненты

Пришла небольшая идея моргающих блоков переходящих из состоний в состояния.

Планировался пул таймеров которые будут выделены под каждый тип состояния и кол-во таймеров будет активно имзеняться чтобы покрыть требования элементов. Пока скрутил до пары таймеров следящих вообще за всеми компонентами.

Рендер one-state элементов бзе таймеров (просто анимации), 500шт ест ~30Мб<

## Что можно доработать

1. через shape outside (inside не работает) или clip-path? менять форму родителя

2. избавиться от массива timer чтобы не раздувать память

3. порезать кол-во пропов передающихся в ребенка

## Конфиг

```.ts
const settings = {
  elements_amount: 5000,                        /* кол-во эл-тов на экране (все рендерятся) |*/
  sorted: true,                                 /* отсортированы по состоянию, дерево состояний см ниже |*/
  debug: false,                                 /* логгирование, показывает начало uuid на каждом эл-нте |*/
  parent_width_px: 1000,                        /* ширина wrapper div |*/
  rerender_speed_ms: 1000,                      /* частота react ререндера через хак (useReducer) |*/

  component: {                                  /* контроллер каждого элемента |*/
    delay_s: { min: 0, max: 1 },                /* задержка в начале анимации моргания |*/
    gap: 0,                                     /* обычный CSS col/row gap |*/
    size: { width: 20, height: 20 }             /* CSS размеры отедльного эл-нта |*/
  },
  timer: { update_rate_s: { min: 2, max: 5 } }, /* частота обновления timer группы, выбирается рандомно в диапазоне |*/
  timers_amount: 10                             /* кол-во таймеров, воспринимай как отдельные процессоры |*/
};
```

> Объяснение по таймерам.
> Все элементы делятся равно на группы чтобы оные обновлялись асинхронно.
>
> Sorted режим отвечает за два разных рендера. Первый прямой: в каком списке элементы создались, в таком и остаются in-place. В sorted можно поиграться в весами (weights) в состоянии `inital_off/starting`, указав там, к примеру 2 и потом 3; будет заметно как после первых тиков ~треть или половина сменят состояние. Во втором режине (он причина создания отдельного объекта с мапами (Map)) объектя ренедяртся в порядке указанном ниже в файле.
>
> Все объекты обновляются в рефах, так что визуально ничего не меняется если не сделать force update, затем и нужен хак с useReducer.
